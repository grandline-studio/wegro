## UI work
- When a task changes how a user-facing UI looks or is laid out (sites, apps, dashboards, components), use the `anti-ai-slop-design` skill. Skip it for backend work and for frontend logic, state, data or test changes that don't change what renders.
- An existing design system, brand, or component library takes precedence over new visual ideas unless I ask for a redesign.
- Never describe UI work as done or visually correct without checking the rendered page at desktop and mobile widths; if you couldn't, say exactly what wasn't verified.
